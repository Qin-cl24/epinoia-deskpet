# 版本管理约定（内测版 / 公开版）

## 双轨策略

| | 本地 main（内测版） | GitHub main（公开版） |
|--|--|--|
| 提交频率 | 随时小提交，想提就提 | 攒够一批，合并成大版本再推 |
| 内容 | 全部实验性改动 | 稳定可用的大版本 |
| 密钥/素材 | 可能包含临时配置 | 绝不包含密钥 |

## 推送流程（攒够 → 合并 → 推送）

1. **本地正常小提交**，不 push
2. 攒到一定程度（功能完成一批 / 版本号升级），把这一段小提交**合并成一个大版本提交**：
   ```bash
   git fetch origin
   git merge origin/main --no-edit        # 先合并远程的新改动
   git reset --soft origin/main           # 软重置到远程，改动进暂存区
   git commit -m "feat: vX 版本说明..."    # 合成为一个大提交
   git push origin main
   ```
3. 推送后本地继续新一轮小提交（内测）

## 备份

- **仓库级**：`git bundle create 备份名.bundle --all`（完整仓库快照，可离线恢复）
- **APK 级**：编译产物已同时存到手机 `Download/`（`AI-桌宠-vX.X.apk`）
- **密钥级**：`~/.config/dsh-vision.key`（权限 600，不进仓库）

## 版本号

- 内测版号跟着功能走：v4.0 对齐原版 → v4.6 Android 16 崩溃修复（+1 每次体验优化）
- 公开版号按大版本：v4 内测版 → 测试稳定后作为 v4.0 发布
